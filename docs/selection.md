# IT朝刊 公開版 記事選定ロジック v2

## 0. 出力
- 1日 最大6件（固定しない）。カテゴリは「インシデント」「新技術」に分けて表示
  - 目安: 各カテゴリ最大3件。足切りを超えた候補だけ載せる（少ない日は2〜4件でよい）
  - 長さの目安: 1トピックは本文3段落以内（1段落1〜2文）＋たとえ1つ＋やること1つ
- タイトル3行 = インシデント上位2件 + 新技術上位1件（新技術行は `T:` を付ける。片方が0件ならもう片方で埋める）
- 1行は全角15文字以内（半角は0.5文字換算）
- 各トピックに目次用の短い見出し `data-short`（全角15文字以内）と、2文字漢字のタグ `data-tag` を付ける

## 0.5 目次タグ（2文字漢字）の決め方
そのトピックを「なぜ選んだか」を1語で示す。上から順に判定し、最初に当てはまったものを付ける。
| タグ | 条件 |
|---|---|
| 続報 | 既出の重大案件のアップデート（§4） |
| 重大 | 重大度S=35（実悪用・KEV掲載・大規模被害） |
| 危険 | 悪用が急拡大中、またはパッチ/回避策がまだない |
| 盲点 | 通常の更新経路や監視から漏れやすい（Store配信のみ、検証環境、設定の落とし穴など） |
| 最新 | 最新度F=30（6時間以内） |
| 話題 | 話題性P≥28 |
| 広域 | 多業種・多製品・多数の利用者に影響 |
| 日本 | 国内の組織・利用者が中心 |
| 世界 | 海外中心で、国内にも波及しうる |
| 注目 | 上記に当てはまらない新技術 |

## 1. 候補の収集
- 対象期間: 前営業日8:00 JST 〜 実行時刻（月曜は金曜8:00〜）
- 発見元（話題性も測る）: Googleトレンド（日本・世界のIT/科学カテゴリ）、はてなブックマーク テクノロジー人気、Hacker News トップ、X トレンド、主要ITメディア（ITmedia、Publickey、BleepingComputer、The Hacker News、SecurityWeek 等）
- 事実確認: 一次情報（ベンダー公式、CISA KEV、JPCERT/JVN/IPA、企業の公表）で裏付けが取れないものは除外

## 2. 除外フィルタ（スコア前に落とす）
1. 一次情報で裏付けが取れない
2. 期間外（公開・更新とも前営業日8:00より前）
3. 既出（履歴 `data/history.json` に同じ事案がある）。ただし §4 の「続報採用」条件を満たす場合は残す
4. 犯行グループの主張だけで、被害企業の公表も信頼できる報道もない
5. 製品の宣伝・PR色が強く、読者が取れる行動がない

## 3. スコア（100点満点）
| 項目 | 配点 | 基準 |
|---|---|---|
| 話題性 P | 0〜35 | 発見元のうち何か所で上位/トレンド入りしたか。4以上=35、3=28、2=20、1=12、0=0 |
| 最新度 F | 0〜30 | 一次情報の公開・更新からの経過時間。〜6h=30、〜12h=24、〜24h=16、〜48h=8、それ以上=0 |
| 重大度/影響度 S | 0〜35 | インシデント: 実悪用・KEV掲載・大規模被害（10万件超/主要サービス停止）=35、CVSS 9以上 or 1万件超の漏えい=26、CVSS 7以上 or 国内有名企業の被害=18、その他=8 / 新技術: 主要ベンダーの一般提供(GA)・今日から使える=35、プレビュー/限定提供=24、公的機関の指針・大規模調査=18、研究・論文=10 |

合計 = P + F + S（足切り: 40点未満は採用しない）

## 4. 既出事案の扱い（重複排除と続報採用）
- 同じ事案の判定キー: CVE番号 / 被害組織名 / 製品名+事象 のいずれかが履歴と一致
- 原則: 既出は除外（同じニュースを読ませない）
- 例外「続報採用」: 次の両方を満たすとき採用し、見出しに【続報】を付ける
  - (a) 初出時の重大度 S が26以上（＝重大案件）
  - (b) 新しい事実がある: 悪用の初確認、パッチ/回避策の公開、被害件数・範囲の拡大、原因の公表、復旧・再停止、公的機関の注意喚起
- 続報には +10 点のボーナス（重大案件の動向は読者価値が高いため）
- 続報は記事内で「前回からの変化」だけを書く（前回の説明は1行に圧縮）

## 5. 国内:海外 = 7:3 の配分
- 「国内」= 日本の組織・利用者が影響を受ける、または日本語の一次情報が主
- 目標: 採用件数Nのうち国内 round(N×0.7) 件（6件なら国内4・海外2、5件なら国内4・海外1、4件なら国内3・海外1）
- 選び方（各カテゴリ最大3件、合計最大6件）:
  1. インシデント・新技術それぞれで、スコア順に並べる
  2. 合計の国内:海外が目標に近づくように、上位から貪欲に採用
     - 国内枠が埋まったら国内候補は飛ばし、海外を採る（逆も同様）
  3. 枠を満たせない場合（候補不足）は、配分より件数を優先し、国内3〜5件まで許容
- 同点時の優先順: 最新度F → 重大度S → 国内

## 6. 件数が少ない日
- 件数は固定しない。足切り40点を超えた候補だけを載せる（水増ししない）
- 1カテゴリが0件になる場合のみ、期間を72時間まで延長して再探索。それでも0件ならそのカテゴリは載せない

## 7. 公開後
- 採用したトピックを `data/history.json` に追記: {date, category, region, key(CVE/組織/製品), S, title}
- 履歴は直近60日分を保持（それより古い事案は「既出」扱いしない）

## 擬似コード
```
cands = collect(window) |> verify_primary |> drop_out_of_window |> drop_claim_only
for c in cands:
    prev = history.match(c.key)
    if prev and not (prev.S >= 26 and c.has_new_fact): drop c
    c.score = P(c) + F(c) + S(c) + (10 if prev else 0)
    c.is_update = bool(prev)
cands = [c for c in cands if c.score >= 40]
pick = select_quota(cands, max_total=6, max_per_category=3, domestic_ratio=0.7,
                    tiebreak=[F, S, domestic])
title = top2(pick.incident) + top1(pick.tech)  # tech line prefixed "T:"
for c in pick: c.tag = first_match(TAG_RULES, c); c.short = shorten(c.title, 15)
history.append(pick)
```
