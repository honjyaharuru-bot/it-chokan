# IT朝刊 公開版 記事選定ロジック v5（2026-11-13）

目標: IT初心者から上級者まで、その日に知るべき情報を1ページ・5分で確認できる。上から読めば重要な順にキャッチできる。

v4からの変更: 「日本を含む世界規模」の事案を最優先にする§3.1を追加し、§5でその事案を国内として数えるようにした（11/13号のMicrosoft 365障害を受けて）。
v3からの変更: カテゴリごとの件数上限（各3件）を廃止しスコア順に。国内:海外を7:3から6:4に。新技術は足切りを超えた候補があれば最低1件。前号の取りこぼし（§2.1）を追加。

## 0. 出力
- 1日 最大6件（固定しない）。カテゴリは「インシデント」「新技術」に分けて表示
 - カテゴリごとの件数上限はない。足切りを超えた候補をスコアの高い順に採用する（少ない日は2〜4件でよい）
 - 新技術: 足切りを超えた候補が1件以上あれば、必ず1件以上入れる（スコア順で入らなくても、最後の1枠を新技術の最上位に入れ替える）
- 5分ルール: 本文（p.what / p.ex / p.act / 漏えいまとめの一覧）の合計は約2,000字以内（1分400字×5分）。dl.facts・出典・用語は数えない
 - 1トピック: 本文2段落以内（1段落1〜2文）＋たとえ1つ＋やること。目安200字
 - 漏えいまとめ: 目安450字（一覧の行を含む）
 - 6件で2,000字を大きく超えるときは、各記事の2段落目を削って収める（件数は減らさない）
- タイトル3行 = インシデント上位2件 + 新技術上位1件（新技術行は `T:` を付ける。片方が0件ならもう片方で埋める）
- 1行は全角15文字以内（半角は0.5文字換算）
- 各トピックに目次用の短い見出し `data-short`（全角15文字以内）と、2文字漢字のタグ `data-tag` を付ける

## 0.1 優先順位と読みやすさ
- 記事の並び順 = カテゴリ内でスコアの高い順（インシデント → 新技術）。目次の番号がそのまま優先順位になる
- 各記事の1段落目は「結論」。初心者が1段落目だけ読んでも、何が起きて自分に関係あるかが分かるように書く
- 2段落目は根拠・技術的な詳細（上級者向け）。バージョンやCVEは dl.facts に入れる
- やること（p.act）は2段階で書く: 「利用者:」（一般の人がすること）と「管理者:」（IT担当がすること）。片方しかない場合は1つでよい

## 0.5 目次タグ（2文字漢字）の決め方
そのトピックを「なぜ選んだか」を1語で示す。上から順に判定し、最初に当てはまったものを付ける。
| タグ | 条件 |
|---|---|
| 漏洩 | 漏えいまとめ記事（§0.6） |
| 続報 | 既出の重大案件のアップデート（§4） |
| 重大 | 重大度S=35（実悪用・KEV掲載・大規模被害） |
| 危険 | 悪用が急拡大中、またはパッチ/回避策がまだない |
| 盲点 | 通常の更新経路や監視から漏れやすい（Store配信のみ、検証環境、設定の落とし穴など） |
| 最新 | 最新度F=30（6時間以内） |
| 話題 | 話題性P≥28 |
| 広域 | 多業種・多製品・多数の利用者に影響 |
| 日本 | 国内の組織・利用者が中心 |
| 世界 | 海外中心で、国内にも波及しうる |
| 注目 | 上記に当てはまらない新技術 |

## 0.6 漏えいまとめ（情報漏えいは1記事に集約）
- 対象: 期間内に公表された、個人情報・顧客情報の漏えい（不正アクセス、委託先経由、設定ミスなど）。2件以上あればまとめ記事にする。1件だけなら通常の記事として扱う
- まとめない事案: サービス停止が主な被害のもの（ランサムウェアによる停止、システム障害）、脆弱性そのものの話題。これらは通常の記事として扱う
- 構成事案の採用条件（すべて満たす）: 一次情報（被害組織の公表）または信頼できる報道で確認できる / 期間内に公表または更新された（§2.1の取りこぼしも可） / 次のどれか: 1,000件以上、国内の有名組織、カード情報・パスワード・本人確認書類を含む
- 既出の事案は §4 の続報条件を満たすときだけ入れ、行頭に【続報】を付ける
- 最大8行。並びは規模（件数）の大きい順。ただし【続報】と、カード情報・パスワードを含む事案は上に置く
- 行の書式: `<li><b>組織名</b><span class="n">規模</span>漏れた情報。入口（原因）</li>` を `<ul class="leaks">` に入れる
- 1段落目: 最大の事案と、今日の事案に共通する手口（例: 委託先経由が多い）を1〜2文で書く
- スコア: 構成事案のうち最高点（続報ボーナスを含む）。1件として数える
- 地域: 構成事案の過半が国内なら国内として数える
- 見出し例: 「個人情報の漏えい公表まとめ（5件）」。data-short 例: 「漏えいまとめ 5件」

## 1. 候補の収集
- 対象期間: 手順書（it-chokan_task_vN.md）§1の固定期間に従う
- 発見元（話題性も測る）: Googleトレンド（日本・世界のIT/科学カテゴリ）、はてなブックマーク テクノロジー人気、Hacker News トップ、X トレンド、主要ITメディア（ITmedia、Publickey、Impress Watch、BleepingComputer、The Hacker News、SecurityWeek 等）
- 事実確認: 一次情報（ベンダー公式、CISA KEV、JPCERT/JVN/IPA、企業の公表）で裏付けが取れないものは除外

## 2. 除外フィルタ（スコア前に落とす）
1. 一次情報で裏付けが取れない
2. 期間外（公開・更新とも期間の開始より前）。ただし §2.1 の取りこぼしは残す
3. 既出（過去記事に同じ事案がある）。ただし §4 の「続報採用」条件を満たす場合は残す
4. 犯行グループの主張だけで、被害企業の公表も信頼できる報道もない
5. 製品の宣伝・PR色が強く、読者が取れる行動がない

## 2.1 前号の取りこぼし
- 前号の期間に公表されたのに、IT朝刊のどの号にも載っていない事案は、次のどれかに当てはまれば今号で採用してよい: 国内の有名組織（ネームバリューがある）、10万件超、カード情報・パスワードを含む
- 採用できるのは翌号の1回だけ。行や本文に公表日（例: 11/9公表）を書く
- 既出チェックで同じ事案（組織名・委託先名・CVE）が見つかれば入れない。委託先経由の事案は、委託先の名前で既出なら入れない（例: アララ経由の各社の公表）

## 3. スコア（100点満点）
| 項目 | 配点 | 基準 |
|---|---|---|
| 話題性 P | 0〜35 | 発見元のうち何か所で上位/トレンド入りしたか。4以上=35、3=28、2=20、1=12、0=0 |
| 最新度 F | 0〜30 | 一次情報の公開・更新からの経過時間。〜6h=30、〜12h=24、〜24h=16、〜48h=8、それ以上=0 |
| 重大度/影響度 S | 0〜35 | インシデント: 実悪用・KEV掲載・大規模被害（10万件超/主要サービス停止）=35、CVSS 9以上 or 1万件超の漏えい=26、CVSS 7以上 or 国内有名企業の被害=18、その他=8 / 新技術: 主要ベンダーの一般提供(GA)・今日から使える=35、プレビュー/限定提供=24、公的機関の指針・大規模調査=18、研究・論文=10 |

合計 = P + F + S（足切り: 40点未満は採用しない。漏えいまとめの構成事案には足切りを適用しない）

### 3.1 日本を含む世界規模の事案を最優先にする
- 対象: 世界規模の事案のうち、日本の利用者・組織にも影響が出ているもの。例: 主要クラウド（Microsoft 365、AWS、Google、Cloudflareなど）の大規模障害、広く使われる製品の悪用、世界同時の攻撃。
- 判定: 次のどちらかで確かめる。(a) 日本で影響が出たという報道や公式発表がある。(b) 事業者が「全地域」「世界中」が対象と発表している。
- 扱い:
  - +15点のボーナスを付ける（続報ボーナスと重ねて付けてよい）。
  - インシデントの1番目に置き、タイトルの1行目に使う。対象が2件以上あるときは、その中でスコア順に並べる。
  - §5の配分では国内として数える。
- 理由: 日本の読者が「今まさに困っている」ことなので、最初に読ませる必要がある。
- 復旧の扱い: 当日中は復旧を追いかけない。期間の終わり（5:30）時点の状況を書けばよい。翌号の期間に新しい事実（復旧・原因の公表など）があれば【続報】の候補にする。

## 4. 既出事案の扱い（重複排除と続報採用）
- 同じ事案の判定キー: CVE番号 / 被害組織名 / 製品名+事象 のいずれかが過去記事と一致
- 原則: 既出は除外（同じニュースを読ませない）
- 例外「続報採用」: 次の両方を満たすとき採用し、見出しに【続報】を付ける
 - (a) 初出時の重大度 S が26以上（＝重大案件）
 - (b) 新しい事実がある: 悪用の初確認、パッチ/回避策の公開、被害件数・範囲の拡大、原因の公表、復旧・再停止、公的機関の注意喚起
- 続報には +10 点のボーナス
- 続報は「前回からの変化」だけを書く（前回の説明は1行に圧縮）

## 5. 国内:海外 = 6:4 の配分（国内優先）
- 「国内」= 日本の組織・利用者が影響を受ける、または日本語の一次情報が主。§3.1の「日本を含む世界規模」の事案も国内として数える
- 目標: 採用件数Nのうち国内 round(N×0.6) 件以上（6件なら国内4・海外2、5件なら国内3・海外2、4件なら国内2〜3、3件なら国内2）
- 選び方: 全候補をスコア順に並べ、上から採用。国内が目標に届かなくなる場合は、海外候補を飛ばして次の国内候補を採る。海外が目標を超えて国内が足りないときも同様
- 候補不足で枠を満たせない場合は、配分より件数を優先する
- 同点時の優先順: 最新度F → 重大度S → 国内

## 6. 件数が少ない日
- 件数は固定しない。足切り40点を超えた候補だけを載せる（水増ししない）
- 1カテゴリが0件になる場合のみ、期間を72時間まで延長して再探索。それでも0件ならそのカテゴリは載せない

- 採用したトピック（漏えいまとめは構成事案ごと）を履歴として扱い、直近60日を既出判定に使う
